# إدارة المعدات — الحالة المحلية الحالية

تطبيق Flutter عربي RTL وباك إند Spring Boot وPostgreSQL فعلي. اكتملت M0/M1 وM2 وM3 وظيفيًا للتطوير المحلي. تشمل M3 مستندات المعدات بإصداراتها، ومركز الانتباه، وإشعارات داخلية محفوظة. تبقى جاهزية الإنتاج وتخزين الملفات الخاص والفحص الأمني للملفات وPush الفعلي خارج ما تحقق؛ لا يُعد V1 مكتملًا.

المسار المنفذ: دخول تطويري ← مساحة مالك تلقائية ← معدة بالاسم والموديل ← مصروف أو إيراد ← دفعات أو تحصيلات مؤرخة داخل العملية نفسها ← استرداد مبلغ دُفع أو حُصّل بالفعل عند الحاجة ← مرفق اختياري ← تعديل موثق أو إلغاء قيد خطأ مع سبب ← الرجوع للسجل والملف بعد التحديث. لا تحتاج مؤسسة أو فريقًا. المصروف كامل/جزئي/غير مدفوع، والإيراد مستلم كاملًا/جزئيًا/غير مستلم. يُطلب اسم الطرف عند إنشاء عملية فيها متبقٍ، وموعد الاستحقاق اختياري عند وجوده. المبلغ يُنقل كنص عشري ويحسب بـBigDecimal/PostgreSQL NUMERIC؛ التسوية والمرفق والاسترداد لا تنشئ عمليات أصلية إضافية.

## قدرات M2 المتاحة الآن

- مصروف لمعدة واحدة، أو أكثر من معدة بمبالغ صريحة مجموعها يساوي الإجمالي، أو مصروف عام بلا معدة. أصل مالي واحد وتسويات واستردادات ومرفقات واحدة؛ حصص المعدات المعروضة مشتقة بالتناسب وتقريب حتمي، وليست دفعات مستقلة.
- مسودة سريعة مرتبطة بمعدة دون مبلغ، مع ملاحظة ومرفقات اختيارية، ثم استكمال الأصل نفسه مع المرفقات نفسها أو استبعاد المسودة؛ لا تدخل المجاميع قبل الاستكمال.
- بحث وتصفية للسجل حسب البيانات المخزنة والتاريخ والنوع والمعدة/العام والحالة والتسوية، مع 30 نتيجة لكل صفحة.
- أي استرداد يعيد متبقيًا إلى أصل بلا اسم طرف يطلب الاسم ويحفظه على الأصل.

## مستندات المعدات والتنبيهات — M3

- لكل معدة مستندات من أنواع الاستمارة والتأمين والفحص الدوري والترخيص/التصريح و«أخرى» باسم يحدده المستخدم. تاريخ الانتهاء اختياري؛ المستند بلا تاريخ يظهر ضمن «بيانات تحتاج استكمال» دون اعتباره ساريًا.
- التجديد ينشئ إصدارًا جديدًا ويُبقي الإصدارات والمرفقات السابقة للقراءة. يمكن تعديل الإصدار الحالي وأرشفة المستند أو استعادته. المرفقات تُربط بالإصدار وتُحمى بصلاحية مساحة العمل.
- حالة الانتهاء تُحسب بتاريخ الرياض. يعرض مركز الانتباه المستندات المنتهية والقريبة من الانتهاء، وتظهر الإشعارات الداخلية في سجل مستقل مع حالة قراءة. تذكيرات 30/7/1/يوم الانتهاء وملخص الأحد للمنتهي تعمل محليًا دون إرسال Push فعلي.
- أرشفة المعدة توقف تنبيهات مستنداتها مع حفظ السجل. واجهتا الهاتف والويب متاحتان؛ لا توجد مستندات للسائق أو المؤسسة أو المشروع في M3.

## التشغيل المحلي

المتطلبات المختبرة: Java 21، Maven Wrapper 3.9.11، Docker/Compose، Flutter 3.47.2 وDart 3.13.2، Python 3 لخادم الويب. الإصدارات والقيود التفصيلية في [ENVIRONMENT](docs/ENVIRONMENT.md).

من جذر المشروع:

```sh
docker compose -f infra/compose.yaml --profile test up -d --wait
```

تعمل قاعدة التطوير على `127.0.0.1:55432` وقاعدة الاختبار المنفصلة على `127.0.0.1:55433`. بياناتهما التطويرية معلنة في Compose؛ ليست بيانات إنتاج. أسماء volumes مقيدة بمشروع `equipment-platform-dev`.

في نافذة أخرى، اضبط `JAVA_HOME` على JDK 21 المثبت لهذا الأمر، ثم شغّل:

```sh
JAVA_HOME=/Users/muath/Library/Java/JavaVirtualMachines/ms-21.0.7/Contents/Home ./scripts/backend-dev.sh
```

أعد تشغيل API بعد تحديث الكود حتى يستخدم ترحيلات Flyway V1–V11؛ بقاء عملية قديمة على 8080 لا يثبت أنها تشغّل آخر commit.

ثم من الجذر:

```sh
cd app
flutter pub get
flutter build web --release --dart-define=API_BASE_URL=http://127.0.0.1:8080/api/v1
python3 -m http.server 8081 --bind 127.0.0.1 --directory build/web
```

افتح `http://127.0.0.1:8081`. فحص API: `http://127.0.0.1:8080/api/v1/health`. يلخص سكربت `scripts/web-dev.sh` أمر البناء والخادم نفسه. لا تخلط `localhost` و`127.0.0.1` في الجلسة الواحدة.

الأرقام التجريبية الوحيدة: `0500000001` و`0500000002`، والرمز التطويري `123456`. لا يُرسل SMS. أول دخول يطلب الاسم مرة واحدة وينشئ مساحة تلقائية. الرمز صالح خمس دقائق، خمس محاولات، وطلب جديد كل 30 ثانية بحد عشرة/ساعة.

للتجربة: أضف «قلاب ١» وموديل «2021» أو «FH16»، ثم مصروفًا جزئيًا `350.00` بدفعة أولى `100.00` وطرف، وأضف دفعة لاحقة من التفاصيل. أضف إيرادًا غير مستلم وطرفًا ثم تحصيلًا لاحقًا. يمكن إرفاق [الفاتورة الاصطناعية](tests/fixtures/synthetic-receipt.png) وفتحها من تفاصيل العملية. تتيح صفحة السجل الرجوع للعملية؛ صفحة المعدة تصفّي سجلها.

## الجوال

مصادر Android وiOS موجودة ضمن `app`. ملف إعداد Android debug يسمح HTTP للعناوين المحلية فقط. إعداد iOS يسمح بالشبكة المحلية للتطوير. نسخة التطبيق الحالية اسمها ومعرّفها تطويريان؛ لا توقيع متجر أو نشر.

```sh
cd app
flutter devices
flutter run -d <device-id> --dart-define=API_BASE_URL=http://127.0.0.1:8080/api/v1
```

لـAndroid Emulator استخدم `http://10.0.2.2:8080/api/v1` مع توجيه اتصال مناسب؛ الباك إند مربوط بالـloopback ولا يُنشر للشبكة. نتائج المنصات التي اختُبرت بالفعل في [HANDOFF](docs/HANDOFF.md)، ولا تعني شاشة بعرض هاتف اختبار جهاز iOS/Android.

## الاختبارات

تشغيل PostgreSQL الاختباري أولًا عبر أمر Compose أعلاه، ثم:

```sh
cd backend
JAVA_HOME=/Users/muath/Library/Java/JavaVirtualMachines/ms-21.0.7/Contents/Home \
  MAVEN_USER_HOME=../.local/maven-user ./mvnw -B -ntp \
  -Dmaven.repo.local=../.local/m2 test
```

`OwnerSliceTest` يشغل خادم HTTP حقيقيًا وقاعدة PostgreSQL الاختبارية. لا H2 أو repository mocks. الاختبارات تفرغ فقط `equipment_test` بعد تحقق صريح من URL، ولا تمس قاعدة التطوير. آخر تشغيل: 50 اختبارًا، 0 فشل/خطأ/تخطٍّ. تغطي قواعد M0–M2، ومستندات المعدة والإصدارات والتجديد والتزامنه، وعزل المساحات، والانتباه والتذكيرات المحفوظة ومنع تكرارها. تقرير التنفيذ: `backend/target/surefire-reports/`.

```sh
cd app
flutter analyze
flutter test
```

آخر تشغيل: 40 اختبار Flutter ناجحًا. تغطي اختبارات M0–M2 السابقة وواجهات مستندات M3 وتجديدها وسجلها والتنبيهات. اختبارات widget تستخدم HTTP doubles؛ نجح اختبار M3 متصل على محاكي iPhone ‏1/1 مع API/PostgreSQL، إضافة إلى اختبار M2 السابق ‏2/2. نجح بناء الويب؛ Web E2E آلي وAndroid لم يُختبرا. التفاصيل في HANDOFF.

## الجلسات والملفات والحدود

- الويب: cookie باسم `equipment_session` من نوع HttpOnly/SameSite=Strict، دون localStorage. `X-CSRF-Token` لكل كتابة بجلسة cookie. CORS لعناوين التطوير المحددة فقط.
- أخطاء التطبيق تعيد `code` و`message` بالعربية. استثناء النقل الموثق: رفض Origin غير المسموح بواسطة Spring يعيد `403` ونصًا عاديًا؛ العميل يتعامل مع الحالة دون افتراض JSON.
- الجوال: opaque Bearer في مخزن النظام الآمن. صلاحية ثماني ساعات، تسجيل خروج يبطل الجلسة فورًا، ولا refresh token. انتهاء الجلسة يعيد الدخول ولا يرسل النموذج القديم تلقائيًا.
- الإنتاج مغلق: يلزم profile `dev` صريح وتفعيل تطويري. `prod` أو مزج `dev,prod` أو تعطيل التطوير يرفض الإقلاع. مزود OTP ومخزن الإنتاج غير مهيئين.
- ملفات التطوير في `.local/objects` خارج DB مع metadata وحالة/checksum في PostgreSQL. PNG/JPEG/PDF حتى 10 MiB، عشرة مرفقات للعملية، حد 25 مليون بكسل و10000 لكل بعد، PDF حتى100صفحة. HEIC غير مدعوم ويحتاج تحويلًا إلىJPEG. الملفات المشفرة/النشطة تُرفض. لا فحص malware فعلي؛ الحالة `DEV_NOT_SCANNED` صريحة. تنظيف تطويري للمرفقات المؤقتة القديمة والملفات اليتيمة يعمل افتراضيًا بعد 7 أيام وبفاصل 24 ساعة قابلين للضبط. تكامل S3 وscanner الإنتاجي غير منفذ.
- كل تنزيل/رفع يعيد التحقق من العضوية. لا bucket عام ولا رابط موقع محفوظ. الملف READY ثابت؛ إعادة bytes نفسها تعيد النتيجة، وbytes مختلفة تُرفض. يعرض التطبيق الصور داخله؛ PDF يُنزّل على الويب ويفتح نسخة مؤقتة على الجوال. الملفات المصدرة تبقى تحت تحكم الجهاز وتحتاج سياسة احتفاظ قبل الإنتاج.
- تدفقات المصروف والإيراد الكاملة/الجزئية/غير المسددة وتسوياتها واسترداداتها وتعديلها وإلغاء الخطأ محفوظة محليًا. الاسترداد حركة مستقلة بتاريخ وسبب؛ `الصافي = مجموع التسويات − مجموع الاستردادات`، و`المتبقي = إجمالي الأصل − الصافي`. لا تعدّل التسويات التاريخية. الإجمالي ثابت بعد أول تسوية أو استرداد للمصروف والإيراد؛ ويمكن تصحيح ربط المصروف وحصصه عند الإجمالي نفسه مع audit؛ الإلغاء يبقي التاريخ ويمنع التسوية والاسترداد الجديدين. لا تعديل/حذف للاسترداد أو مرفق خاص به في هذه الشريحة. تعمل مجاميع المصروف النشط للمساحة والمعدة دون مضاعفة المصروف المشترك؛ العام يظهر في المساحة فقط. البحث والتصفية ومسودة الصورة واستكمالها منفذة محليًا. Q-02 مغلق بقرار D-20، وM2 مكتملة وظيفيًا للتطوير؛ تخزين الملفات الخاص وفحصها الإنتاجي مؤجلان إلى Production Readiness. التخزين الخاص المربوط بـS3 والمراجعة/تقارير الفترات والأرشفة والفريق والتنبيهات غير منفذة. لا GPS أو OCR أو بوابة دفع.

لإيقاف الخدمات دون حذف البيانات:

```sh
docker compose -f infra/compose.yaml stop
```

ثم `docker compose -f infra/compose.yaml --profile test up -d --wait` لإعادتها. أوقف عمليتي API وخادم الويب بـCtrl+C. لا تستخدم `down -v` للبيانات التي تريد الاحتفاظ بها. لا سكربت reset لقاعدة التطوير؛ الاختبارات وحدها تعيد بيانات قاعدتها المعزولة.

إعادة توليد fixture فقط:

```sh
java -Djava.awt.headless=true scripts/SyntheticReceipt.java
```

عقد API في [OpenAPI](contracts/openapi.yaml). الإصدارات، نتائج التنفيذ الفعلية، المراجعات، وأي فجوات NOT RUN تُحفظ في [HANDOFF](docs/HANDOFF.md) و[أدلة التحقق](docs/evidence/).
