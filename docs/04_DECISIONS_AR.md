# سجل القرارات وحالة الاعتماد

## كيفية قراءة الحالات
CONFIRMED: قرار تجاري ظهر اعتماده صراحةً في المحادثة.
BASELINE: اختيار تنفيذ مقترح استُخدم لتجهيز الانتقال للبرمجة؛ ليس ادعاءً بأن المستخدم ناقش كل تفصيل واعتمده.
OPEN: يحتاج قرارًا قبل الجزء المتأثر أو قبل الإطلاق. لا يعطل الأجزاء المستقلة.
أي تغيير لاحق يُسجل بتاريخ وسبب ومرجع موافقة المستخدم، مع تحديث الملفات والاختبارات المتأثرة.

## خط أساس التنفيذ
| ID | الاختيار | حدود اعتماده في هذه الحزمة |
|---|---|---|
| B-01 | Flutter للجوال والويب | اتجاه التنفيذ المقترح؛ لا React إضافي دون سبب وموافقة |
| B-02 | Spring Boot modular monolith + PostgreSQL | خط الأساس، الإصدارات تختار بعد الفحص الرسمي |
| B-03 | Object Storage خاص بواجهة S3، وmetadata في DB | اتجاه التخزين؛ الشركة والمنطقة والحساب والتكلفة OPEN |
| B-04 | عربية RTL، SAR، تاريخ ميلادي واضح، Asia/Riyadh | Defaults معلنة قابلة للمراجعة، لا multi-currency أو ترجمة كاملة تلقائيًا |
| B-05 | مساحة افتراضية تلقائية بلا نموذج مؤسسة | تطبيق مبدأ البداية البسيطة؛ لا شاشة إنشاء تجاري إلزامية |
| B-06 | صور وPDF، لا Offline كامل ولا OCR | حد التنفيذ الحالي، صيغ الأجهزة وحدود الرفع تُوثق |
| B-07 | FCM + outbox/task state في PostgreSQL | لا ادعاء تفعيل الإنتاج، مزود OTP مستقل وغير مختار |
| B-08 | قائد وكاتب واحد ومراجع مستقل وUX عند الحاجة | ترشيح دورة العمل، لا حاجة لشراء عدة اشتراكات |

## تفاصيل لم تحسم
ارجع إلى OPEN_QUESTIONS.md. الأهم: أثر الاسترداد على أصل الالتزام، تغيير التوزيعات بعد الدفعات،
تفاصيل رفض/تعديل عمليات الفريق المعتمدة، التعامل مع تغيير انتماء المعدة لمؤسسة على السجلات القديمة،
تفاصيل العقود، ومزودي الخدمات والسياسات قبل النشر. لا تتخذ هذه القرارات خفية.

## قيد المخططات
الصورة العامة السابقة لا تتفوق على D-02/D-03/D-11. اختلافات الرسم تُصحح في التنفيذ لا العكس.
الصور الثلاث التفصيلية مراجع أقرب للفلو، لكنها لا تثبت اكتمال جميع الحقول أو صحة الأرقام/التواريخ التجريبية.
