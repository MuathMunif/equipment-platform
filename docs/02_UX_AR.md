# الفلو ومواصفات الشاشات — مرجع التنفيذ
الحالة: الفلو مبني على القرارات المعتمدة؛ التفاصيل البصرية وحالات الشاشات هنا BASELINE للتنفيذ والتحسين.
لا تجعل أي تفصيل مقترح شرطًا جديدًا يخالف بساطة المنتج.

## قاعدة الحسم عند اختلاف الصورة
النص المعتمد مقدم على الصورة. المخطط العام القديم يحتوي اقتراح إعداد مساحة عمل وحقول نوع/ماركة/لوحة
لا تُنسخ كمتطلبات إجبارية. لا زر حذف عشوائي لعملية مسجلة. الألوان والأيقونات ليست هوية نهائية.
الصور الفعلية المتاحة في design/references موثقة في design/README_AR.md.
لا يوجد ملف Figma أو prototype تفاعلي مُثبت في الحزمة. لا تزعم وجوده.

## رحلة F-01 — المالك وحده
جوال => OTP => الاسم للحساب الجديد => مساحة عمل افتراضية تلقائية => حالة لا معدات => إضافة الاسم والموديل
=> صفحة المعدة => إضافة مصروف => تحديد مبلغ ونوع مع تاريخ اليوم => حفظ => تفاصيل العملية => السجل.
لا مرحلة إلزامية للمؤسسة أو المشروع أو الفريق. إذا الاسم قُدم قبل OTP فلا تكرره بعده.
قبول الدعوة مسار منفصل عن إنشاء مساحة جديدة. مستخدم واحد ومساحة واحدة لا يحتاج شاشة اختيار مساحة.

## رحلة F-02 — مبلغ متبقٍ
إضافة إيراد => كامل افتراضي ظاهر => اختيار جزئي/غير مستلم => مبلغ أول دفعة عند الجزئي + تاريخها
=> اسم الطرف المطلوب عندما يوجد متبقٍ => موعد اختياري => حفظ => تفاصيل الإجمالي/المستلم/المتبقي
=> إضافة تحصيل لاحق للعملية نفسها => تحديث الحالة آليًا.
نظيرها للمصروف بألفاظ «مدفوع/متبقي عليك». لا تخلط «اعتماد» مع «سداد».

## رحلة F-03 — مرفق لاحق أو صورة فقط
من العملية الموجودة => إضافة مرفق => اختيار/تصوير => رفع => تحقق وفحص => جاهز للعرض.
فشل الرفع لا يلغي العملية ولا يعيد إنشاءها. إعادة المحاولة تخص المرفق.
من إجراء سريع/السائق => إرسال صورة فقط => «بانتظار الاستكمال» خارج المجاميع => مخول يكمل نفس السجل.
لا تعِد بأن الصورة محفوظة سحابيًا قبل إقرار السيرفر. عند مسودة محلية وضّح أنها على الجهاز فقط.

## رحلة F-04 — المستند
المعدة => المستندات => إضافة نوع => ملف اختياري وفق نوع الإجراء => إضافة تاريخ إن طلب تنبيه
=> حفظ => إظهار حالة فعلية => تجديد => نسخة جديدة حالية => إيقاف تذكير القديمة وحفظ التاريخ.
إغلاق إشعار لا يعني تجديد مستند. المستند المفقود بياناته لا يعرض بعلامة «ساري».

## رحلة F-05 — بلاغ وصيانة
المعدة => بلاغ => وصف وصور اختيارية => مفتوح => جارٍ العمل أو إغلاق مباشر
=> عند حدوث تكلفة: إنشاء مصروف واحد وربطه => إغلاق البلاغ مستقل عن السداد.
المصروف الدوري يمكن إدخاله مباشرة دون بلاغ، والبلاغ يمكن إنهاؤه دون مصروف.

## رحلة F-06 — الفريق
المزيد/الإعدادات => دعوة باسم وجوال ودور => نطاق وصول => دعوة/قبول/تحقق
=> الدخول لمساحة موجودة => رؤية الموارد المسموحة فقط.
السائق => صورة/طلب مالي => إرسال للمراجعة => مخول يستكمل/يؤكد => ظهور في المجاميع بعد الاعتماد.
المحاسب المدخل نيابة عن السائق يسجل بصفته الحقيقية. توقف العضوية يلغي الوصول لا السجلات.

## رحلة F-07 — التصحيح والأرشفة
تفاصيل العملية => تعديل مسموح أو إلغاء بسبب => سجل التغييرات => تحديث المجاميع.
استرداد المال الحقيقي مسار مرتبط مختلف عن الإلغاء الخطئي.
تفاصيل المعدة => أرشفة وتأكيد => اختفاؤها من النشطة => سجل تاريخي ومستحقات مستمرة.

## التنقل
الجوال: الرئيسية / المعدات / السجل. «المزيد» منفذ للإعدادات والفريق والاختياريات، لا قسم تشغيل إضافي ثقيل.
الويب: تنقل جانبي أو هيكل مناسب مع الوظائف نفسها. عند الاتساع يمكن قائمة وتفاصيل جنبًا إلى جنب.
إظهار المؤسسة/المشروع الاختياري عند الحاجة دون كتل فارغة أو خطوات معطلة.
لا توجد قوائم GPS أو خرائط أو قسم «الفواتير» الذي يكرر سجل المصروفات والإيرادات.

## نموذج المصروف الأساسي
- عند البدء من المعدة: تحدد تلقائيًا ويمكن تغييرها ضمن الصلاحيات، لا اختيار مزدوج.
- المبلغ والتصنيف، تاريخ اليوم مع تعديل؛ لا عملة متعددة في خط الأساس.
- «دفعته كاملًا» واضح؛ الجزئي/غير المدفوع يفتح فقط الحقول المتعلقة به.
- صورة/PDF وملاحظة اختيارية. اسم الطرف فقط عند وجود متبقٍ.
- حفظ => إقرار فعلي من الخادم => تفاصيل العملية. وضّح حفظ العملية وفشل المرفق كلًا على حدة.

## الملخصات والبحث
رئيسية غير مزدحمة. نستخدم «المبالغ المستلمة/المدفوعة خلال الفترة» و«متبقي لك/عليك حتى اليوم».
صفحة المعدة تميز إجمالي العمليات عن الدفعات. العام لا يُخفى داخل أرقام المعدة.
البحث في الحقول المكتوبة؛ لا ادعاء بالبحث في محتوى صور الفواتير.
وحدة التقارير الأولى هي هذه الملخصات والسجل المصفّى؛ الرسوم والتصديرات المتقدمة ليست شرط البداية.

## جميع الشاشات
حالات تحميل/فراغ/خطأ/بدون صلاحية/انتهاء جلسة/عدم اتصال/حفظ جارٍ/نجاح/تعثر جزئي.
لا زر قابل للضغط دون تنفيذ أو تفسير. لا إشعار «نجح» قبل تأكيد السيرفر.
حماية المدخلات عند الرجوع أو الخطأ، تحذير مغادرة عند الحاجة، دون مزامنة Offline كاملة.
التعامل مع انتهاء الجلسة لا يرسل طلبًا باسم مساحة مختلفة بعد إعادة الدخول.
اختبر العربية وRTL والنص المختلط والأرقام وPDF واللوحة والموبايل، والتكبير والوصول بلوحة المفاتيح.
تنسيق التاريخ يجب أن يكون موحدًا وغير ملتبس؛ لا تعتمد 09/24/2026 في صورة كقرار نهائي للعرض.
ابدأ بتواريخ ميلادية واضحة وAsia/Riyadh كاقتراح موثق، دون ادعاء أن سنة الموديل هي تاريخ.

## تعريف اكتمال UX
فلو قابل للتجربة وليس صورًا فقط؛ صور Mobile/Desktop من التطبيق العامل مع بيانات تجريبية محددة.
لا توضع روابط تجريبية لم تُختبر، ولا لقطات تُقدَّم على أنها اختبارات لم تُنفذ.
لا يبنى النموذج بمشروع React منفصل بدل Flutter المتفق عليه تقنيًا فقط لتسريع إخراج شكل جميل.
