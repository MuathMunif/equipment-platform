# حالة التسليم — M0/M1 وشريحتان من M2

تحديث 2026-09-24. الفرع `work/m0-m1`، وآخر التزام تنفيذ قبل مزامنة هذه الوثائق `b6a47eb` (الإيراد والتحصيلات). M0 وM1 مكتملتان **محليًا**، ونُفذت شريحتان من M2: المصروف والإيراد بحالات كامل/جزئي/غير مسدد وتسويات متعددة مؤرخة. بقية M2 وM3–M7 وV1 الإنتاجية غير مكتملة. لا تطوير ميزة جديدة جارٍ بعد طلب المالك إيقافه؛ المهمة الحالية مزامنة وثائق وسياسة وكلاء فقط، دون وكيل فرعي.

## المسار العامل
- دخول تطويري معزول بهويتين اصطناعيتين، اسم للمالك الجديد فقط، ومساحة مالك تلقائية؛ جلسة محفوظة وخروج يبطلها.
- معدة بالاسم والموديل النصي فقط، مرجع داخلي، قائمة وبحث بالاسم/المرجع وتفاصيل.
- مصروف كامل/جزئي/غير مدفوع، وإيراد مستلم كاملًا/جزئيًا/غير مستلم. اسم الطرف مطلوب عند وجود متبقٍ والموعد اختياري. دفعات المصروف وتحصيلات الإيراد مؤرخة في الأصل نفسه، بأرقام عشرية دقيقة ومفاتيح إعادة طلب؛ منع التجاوز والتكرار من الخادم.
- مرفقات PNG/JPEG/PDF بعد حفظ العملية، مع حالة وإعادة محاولة وعرض/تنزيل محميين؛ المرفق لا يضيف عملية أو تسوية مالية. السجل والتفاصيل يسترجعان البيانات المحفوظة.
- تفويض المالك وعزل مساحة العمل في الخادم، بما في ذلك الملفات وإعادة الطلب وإبطال العضوية. الواجهة Flutter عربية RTL على الويب، ومسار تكامل واحد نجح على محاكي iOS مع API/PostgreSQL فعليين.

## التشغيل المحلي الذي جُرّب
من `/Users/muath/Desktop/equipment-platform`:

```sh
docker compose -f infra/compose.yaml --profile test up -d --wait
JAVA_HOME=/Users/muath/Library/Java/JavaVirtualMachines/ms-21.0.7/Contents/Home ./scripts/backend-dev.sh
```

من نافذة أخرى:

```sh
./scripts/web-dev.sh
```

PostgreSQL dev/test على loopback `55432/55433`، API على `8080`، والويب على `8081`. افتح `http://127.0.0.1:8081`؛ health في `http://127.0.0.1:8080/api/v1/health`. الهوية التجريبية `0500000001` أو `0500000002` والرمز `123456`؛ لا SMS. **أعد تشغيل API والويب إذا كانت عمليتاهما سابقتين لآخر commit**: رجوع HTTP 200 وحده لا يثبت أن العملية تستخدم V3 أو بناء Flutter الحالي. الخدمات المؤقتة `8082/8083` المستخدمة في دليل M2 أُوقفت بعد التحقق.

## نتائج التحقق الحالية
- PASS في آخر فحص حالة على المصدر الحالي: `16` اختبار backend مع HTTP/PostgreSQL الاختبارية، `0` فشل/خطأ/تخطٍّ؛ و`9` اختبارات Flutter unit/widget، `0` فشل. اختبارات widget تستخدم HTTP doubles.
- PASS في آخر فحص تنفيذ M2: `flutter analyze`، وبناء Flutter web release، واختبار تكامل واحد على محاكي iOS مع API/PostgreSQL حقيقيين. اختبار iOS لم يُعد تشغيله أثناء فحص الحالة الوثائقي.
- PASS موثق سابقًا: مسار ويب حي للمصروف الجزئي/غير المدفوع والدفعات، ومسار إيراد غير مستلم ثم تحصيل داخل الأصل نفسه. دليل [المصروف](evidence/M2_EXPENSE_SETTLEMENTS.md) ودليل [الإيراد](evidence/M2_INCOME_SETTLEMENTS.md). أدلة M1 الأساسية في [M1_ACCEPTANCE](evidence/M1_ACCEPTANCE.md) و[API_MANUAL_CHECKS](evidence/API_MANUAL_CHECKS.md). أرقام M1 التاريخية `12 backend + 7 Flutter` ليست نتائج النسخة الحالية.
- NOT RUN في فحص الحالة الأخير: إعادة اختبار تكامل iOS وE2E الويب. NOT TESTED لإصدار الإنتاج: Android native، أجهزة فعلية، منتقي الملفات/PDF الأصلي على iOS، S3/scanner/SMS حقيقي، نشر، وتدريب استعادة backup. ملف اختبار iOS يُحقن بدل منتقي الملفات؛ الرفع وKeychain وAPI حقيقية.

## الحدود والعيوب المعروفة
- التخزين الفعلي `.local/objects` خلف adapter تطويري؛ PostgreSQL تحفظ metadata والحالة والبصمة، والملف `DEV_NOT_SCANNED`. لا تخزين S3 خاص أو malware scanner فعلي، ولا مزود OTP إنتاجي. التطبيق يرفض بدء profile إنتاجي غير مهيأ. لا خدمة خارجية مدفوعة مطلوبة للتطوير المحلي.
- بقية M2: التعديل المسموح، البحث/التصفية المالية الموسعة، مسودة الصورة واستكمالها، وتكامل التخزين الخاص المختار. M3–M7 لم تبدأ. لا مصروف عام/مشترك، استرداد، أرشفة، فريق، إشعارات أو تقارير فترات مكتملة. قرارات [OPEN_QUESTIONS](OPEN_QUESTIONS.md) لم تُحسم خفية.
- عيب UX منخفض الأولوية: تاريخ الدفعة داخل جملة عربية قد يظهر باتجاه بصري مختلف عن تاريخ العنوان؛ القيمة المخزنة صحيحة. بعض رسائل المرفق في backend ما زالت تسمي العملية «مصروفًا» حتى مع الإيراد.
